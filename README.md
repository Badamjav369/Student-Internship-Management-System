# Оюутны дадлагын нэгдсэн удирдлагын веб систем (Project-2)

Frontend: энгийн **HTML + CSS + JavaScript (ES modules) + Web Components** — framework, bundler хэрэггүй. Backend: **Cloudflare Worker + D1 (SQLite) + R2** (`server/`).
Долоон дүр: **оюутан, удирдагч багш, дадлага удирдагч, байгууллагын төлөөлөгч, комиссын гишүүн, тэнхмийн эрхлэгч, тэнхимийн админ**.

## 1. Локалд ажиллуулах

Node.js **22.13 буюу түүнээс дээш** хэрэгтэй (`node -v`). Өөр юм суулгахгүй — `npm install` ч хэрэггүй.

```powershell
cd "D:\University\2026-2 Fall\Бакалаврын судалгааны ажил\Project-2"
npm run dev          # эсвэл: node dev-server.mjs        → http://localhost:5173
npm run dev:reset    # өгөгдлийг демо төлөвт нь буцааж асаана (.data хавтсыг шинээр үүсгэнэ)
```
Cloudflare дээрхтэй **ижил** backend код Node-ийн суурилагдсан SQLite (`.data/local.sqlite`), файлын систем (`.data/files`) дээр ажиллана. Анх асаахад хүснэгт, демо өгөгдөл (`scripts/demo.sql`), демо файлууд автоматаар үүснэ. Урилга, нууц үг сэргээх холбоос терминалд (`[mail] ...`) хэвлэгдэнэ. Зогсоохдоо `Ctrl + C`; өөр порт: `$env:PORT=8080; npm run dev`. Интерфэйсийн файл (`src/`) засаад **F5** дарахад шинэчлэгдэнэ. `server/`, `migrations/` засвал сервер өөрөө дахин асна (`npm run dev` үед).

> Интернэт байвал **Rubik** фонт Google Fonts-оос ачаалагдана; байхгүй бол системийн фонтоор харагдана.

## 4. Архитектурын гол шийдвэр

- **Хариуцлага тусгаарласан**: хуудас (`pages/`) өгөгдлийг зөвхөн `data/*-api.js`-ийн функцээр (`/api`) авна; DOM-ыг `core/dom.js`-ийн `h()`-ээр бүтээнэ (текст нь `textNode` тул `innerHTML`-ийн XSS эрсдэлгүй).
- **Web Components** (`<app-shell>`, `<progress-path>`, `<status-badge>` …): тохиргоог attribute, объектыг property, үйлдлийг event-ээр дамжуулна. Shadow DOM **ашиглаагүй** (загвар тусгаарлах хэрэгцээгүй, theme token шууд үйлчилнэ). `connectedCallback` давтан дуудагдахад listener давхардахгүй, `disconnectedCallback` дээр цэвэрлэнэ.
- **CSS `@layer`**: `reset → primitive → semantic → brand → base → layout → components → pages → utilities`. Сүүлийн давхарга давуу тул `!important` хэрэггүй. ⚠ Үүнээс үүдэх нэг дүрэм: `hidden` атрибутыг `utilities` давхаргад `display:none` болгосон — эс бөгөөс components дахь `display` түүнийг давна.
- **Табууд (Дадлагын байгууллага)**: `role=tablist/tab/tabpanel`, сум/Home/End товчоор шилжинэ. Таб солиход router **дахин ажиллахгүй**, skeleton гарахгүй: өгөгдлийг хуудас нээгдэхэд нэг дор татаж, самбар бүрийг анх нээхэд л бүтээж хадгална; зөвхөн URL (`history.replaceState`) шинэчлэгдэнэ. Хүсэлт илгээх/цуцлахад харагдаж буй самбар шууд, бусад нь дараа нээгдэхэд шинэчлэгдэнэ. Хайлт 250 мс хүлээж илгээнэ, хуучин хариу шинэ үр дүнг дардаггүй.
- **Толгой мөр (topbar) байрандаа**: `.topbar` нь `position: sticky; top: 0` + бүдэг фон (`backdrop-filter`) — өмнөх Project-ийн адил гүйлгэхэд профайл, theme солих, хонх хэзээд харагдана. Нарийн дэлгэц дээр хонхны жагсаалтыг хонхонд биш толгой мөрөнд тулгаж, дэлгэцийн өргөнд багтаадаг.
- **Баримт үзэгч**: PDF, зурагтай файл бүрийн хажууд «Үзэх» (эсвэл файлын нэр) гарч, `components/doc-viewer.js` баримтыг **ном шиг** нээнэ: нүүр ганцаараа, дараа нь хоёр хуудас зэрэг (утас, нарийн дэлгэц дээр нэг хуудас), хуудас эргэхэд жинхэнэ 3D хуудас зүүн/баруун ирмэгээрээ эргэж сүүдэр тусна. Хуудас эргүүлэх: товч, ←/→, Home/End, хуудсан дээр дарах, утсанд гулсуулах, доорх гулсуур, хуудасны дугаар бичиж очих. **Текстээр хайх** (Ctrl+F эсвэл `/`): олдсон үг хуудас дээр тодорч, тохиролтоор шилжинэ (скан зураг бол текстгүй тул хайхгүй). **Бүтэн дэлгэц** (товч эсвэл `F`): кино шиг хуудас дэлгэцийг бүтнээр эзэлж, хөдөлгөөнгүй үед товчнууд алга болно. Томруулах (+/−). PDF.js нь `src/vendor/pdfjs/` дотор (Apache-2.0) бөгөөд **зөвхөн «Үзэх» дарахад** ачаалагдана; харагдаж буй хуудас, хөрш хуудсыг л зурдаг тул сайтын анхны ачаалал, гүйцэтгэлд нөлөөлөхгүй. Файлыг `/api/files/:id` (эрхийн шалгалттай)-аар уншина. Word, Excel, PowerPoint үзэгдэхгүй — зөвхөн «Татах».
- **Оюутны файл**: гэрээний скан, тайлан, газар санал болгох хавсралтыг оюутан **зөвхөн PDF**-ээр оруулна (сервер, маягт хоёуланд шалгана); дэвтрийн хавсралт PDF/PNG/JPEG. Тайлангийн шаардлагын жагсаалтад зөвхөн PDF.
- **Мэдэгдэл**: хонх сүүлийн 5-г харуулж, «Бүх мэдэгдэл» нь `#/<дүр>/notifications` хуудас руу (Бүгд / Уншаагүй шүүлтүүр, «Бүгдийг уншсан болгох», «Цааш үзэх» — 8-аар) аваачна. Мэдэгдэл дээр дарвал уншсан болж холбоос руу очно. Мэдэгдэл хэрэглэгч + дүрээр тусдаа.
- **Гуравласан гэрээ**: «Гэрээ», «Скан хувь» гэсэн 2 файлын хавтан; төлөв (Бэлэн / Байршуулаагүй / Байршуулсан / Буцаагдсан) нь хавтан бүрийн буланд жижиг тэмдэглэгээ. Он сар өдөр, тоон хавтан байхгүй; баталгаажуулалтыг толгой мөрийн нэг тэмдэглэгээ харуулна.
- **Гуравласан гэрээ — гурван хэлбэр**: гурван тал — **оюутан**, **дадлага удирдагч (байгууллага)**, **тэнхмийн эрхлэгч**. Оюутан гэрээ `filled` / `returned` үед хэлбэрээ сонгоно («Хэлбэр солих»-оор өөрчилнө; нэг ч гарын үсэг зурагдсан бол солих боломжгүй):
  1. **Цаасан** (`mode=paper`): оюутан системийн загвараар үүссэн гэрээг татаж, гурван талаар гаднаас гарын үсэг зуруулаад **скан PDF-ийг байршуулна** → `scanned` → эрхлэгч баталгаажуулах (`approved`) эсвэл шалтгаантай буцаах (`returned`).
  2. **Дэлгэцэнд зурах** (`mode=touch`): гэрээг системд нээж, хуруу/үзгээр (`components/signature-pad.js`, pointer events — утас, таблет, хулгана) гарын үсгээ зурна. Оюутан, дадлага удирдагч ямар ч дарааллаар, **эрхлэгч хамгийн сүүлд**. Гурван тал нэг хуудсанд «Гарын үсэг» жагсаалтаар хэн зурсан/хүлээж байгааг харна; хуудас 4 секунд тутам шинэчлэгдэх тул нөгөө тал зурмагц бусдад шууд (polling, push биш) харагдана. Эрхлэгчийн гарын үсэг гэрээг автоматаар баталгаажуулна (`approved`, дадлага `planning`/`in_progress` болно). Дадлага удирдагч байгууллагын **тамганы зургийг** («Гэрээ» хуудас → Тамга; PNG/JPEG ≤ 300KB, `organizations.seal`) нэг удаа оруулбал өөрийн гарын үсгийн хажууд баримтад хавсарна.
  3. **Тоон гарын үсэг** (`mode=digital`): гарын үсэг бүрийг и-мэйлээр ирсэн 6 оронтой нэг удаагийн код (10 минут, 5 оролдлого, 10 минутад 5 код) + «өөрийн цахим гарын үсгээр баталгаажуулж байна» зөвшөөрлөөр хийнэ; IP, хөтөч аудитад хадгалагдана. Үлдсэн дараалал, шинэчлэл 2-той ижил.
  **Баталгаажуулалт**: баримтын агуулгын SHA-256 хэш (`contracts` хэсгүүд) + гарын үсэг бүрийн `proof = HMAC-SHA256(SIGNING_SECRET, хэш|тал|хэрэглэгч|цаг|хэлбэр)`. «Шалгах» товч агуулга, гарын үсэг өөрчлөгдсөн эсэхийг шалгана (`/verify`). Гарын үсэг орсны дараа гэрээний агуулга өөрчлөгдвөл «Шалгах» алдаа заана; эрхлэгч гэрээг буцаахад (шалтгаантай) гарын үсгүүд цэвэрлэгдэж дахин зурна. API: `GET|POST /api/{student/contract|mentor/contracts/:id|head/contracts/:id}` + `/document` (хэвлэх/PDF), `/sign`, `/sign/code`, `/verify`; `POST /api/student/contract/mode`; `PUT /api/mentor/seal`. DB: `contracts.mode`, `contract_signatures`, `sign_codes`, `organizations.seal` (`migrations/0004_contract_signing.sql`).
  **Хууль зүйн хязгаар**: «Цахим гарын үсгийн тухай хууль»-д энгийн *цахим гарын үсэг* (4.1.10) ба *тоон гарын үсэг* (лицензтэй гэрчилгээжүүлэх байгууллагын гэрчилгээтэй PKI; гараар зурсантай тэнцүү — 6.3) ялгагдана. Системийн 2, 3-р хэлбэр нь **энгийн цахим гарын үсэг** — тэнхим дотоод журмаар хүлээн зөвшөөрсөн тохиолдолд хэрэглэнэ. Хуулийн хүчин төгөлдөр «тоон гарын үсэг» болгохыг хүсвэл e-ID Mongolia (Gerege Systems; RP-API: нэвтрэх/гарын үсэг/байгууллагын тамга, зөвхөн хэш дамжина, PIN2) зэрэг лицензтэй үйлчилгээтэй холбоно — гэрээ, түлхүүр шаардлагатай тул **одоогоор холбоогүй**; `sign()` дахь баталгаажуулалтын алхмыг (`checkCode`) provider-оор солих байдлаар зохион бүтээсэн.
- **Комиссын оноо**: гишүүн бүр шалгуур бүрийн оноогоо өөрөө оруулна (бусдын оноог харахгүй); бүх гишүүн оруулсны дараа оноо нэгтгэгдэж удирдагч багш баталгаажуулна. Улирлын тохиргоо «тохиролцоо» бол зөвхөн дарга оруулна. Оноо оруулах талбарыг дадлага удирдагчийн үнэлгээтэй `components/score-fields.js`-ээр хуваалцана.
- **Ажлын төлөвлөгөө**: нэг үед нэг л төлөвлөгөө (хувилбар, таб байхгүй). Харах горим — (1) шийдвэрийн өнгөт зурвас (Батлагдсан / Санал бичиж буцаасан / Хянагдаж байна + огноо), (2) дадлага удирдагчийн санал (бүдэг шар, мөр дүүрэн), (3) «Ажлын хуваарь» хайрцаг — дээд талд төлөвлөгөөний мэдээлэл, зураасын доор дугаар + хугацаа + ажилтай босоо шугам. Байхгүй эсвэл буцаагдсан бол мөн хуудсанд «Төлөвлөгөө илгээх» товчтой маягт гарч, илгээсэн төлөвлөгөө өмнөхийг солино.
- **Дадлагын дэвтэр**: таб/шүүлтүүргүй — бүх тэмдэглэл нэг дэвтэрт, долоо хоног бүр гарчигтай (шинэ нь дээрээ, долоо хоног доторх өдөр Даваа→Баасан), өдөр бүр нэг карт (ирээдүйн өдөр бүдэг). Өнөөдөр бичигдээгүй бол автоматаар нээгдэнэ. Оролтын маягт: зүүн талд «Гүйцэтгэсэн ажил» (өргөн), баруун талд «Ажилласан цаг» (`цаг` нэгжтэй) + «Хавсралт», доор баруун талд «Хадгалах»; нарийн дэлгэц дээр дээрээс доош.
- **Үнэлгээ**: онооны хавтан бүрийн дээр жижиг төлөв (Хүлээгдэж буй / Баталгаажсан / Комисс үнэлж байна / Дууссан / Хойшлогдсон / Хангалтгүй); том утга нь оноо (`— / 40` гэх мэт) тул «Хүлээгдэж буй» гэсэн том бичвэр байхгүй.
- **Тайлан, Хамгаалалт, Удирдамж**: «Дадлагын байгууллага»-ын хэлээр. Тайлан — шаардсан файл бүр нэг хавтан (сонгоход шууд ноорогт орно), нэг үед нэг л тайлан (хувилбар, таб байхгүй): дээд мөрөнд хоёр хайрцаг (хүлээн авах хугацаа: эхлэх – дуусах; удирдагч багшийн санал), файл бүр өгсөн огноотой; засвар шаардсан бол өмнөх файлууд ноорогт үлдэж, оюутан солоод «Тайлан илгээх» товчоор дахин илгээнэ; илгээсэн бол файлуудыг зөвхөн харна. Хамгаалалт — нэг мөрөнд 2 хайрцаг (онцолсон огноо + том цаг; хэлбэр + байршил/холбоос) ба дарга/багш/оюутан бүгд нэг хайрцагт. Удирдамж — «Зарлал», «Заавар, маягт» гэсэн 2 таб. Хуудас доторх табыг `core/tabs.js` нэг газраас бүтээнэ (ARIA, сум/Home/End, тоо, төлвийн цэг). Хамгийн их мэдээлэлтэй төлөв дээр загварчилж, хоосон/бага мэдээлэлтэй төлвүүд нь тэр загварт багтдаг. Үйл явц тайлбарлах текст (тайлангийн «дараалал», хамгаалалтын «бэлтгэл» жагсаалт, «дараа юу хийх» гэх мэт) оруулаагүй.
- **Улирал бүрийн шаардлага (төлөвлөгөө, дэвтэр)**: админ улирал үүсгэхдээ «Оюутнаас шаардах» хэсгээс **Ажлын төлөвлөгөө**, **Дадлагын дэвтэр**-ийг сонгоно (анхдагчаар хоёулаа). Улирал эхлэх хүртэл (ноорог) тохиргооноос өөрчилнө, идэвхжсэний дараа өөрчлөх боломжгүй. Төлөвлөгөө шаардаагүй бол гэрээ баталгаажмагц дадлага шууд эхэлнэ (`planning` төлөв алгасагдана), оюутны шатны жагсаалтаас «Ажлын төлөвлөгөө» хасагдана. Дэвтэр шаардаагүй бол тэмдэглэл, тасалсан өдөр, дэвтрийн хоцролт тооцогдохгүй, тайлангийн хуудаснаас дэвтрийн PDF хасагдана. Хоёр тохиолдолд оюутан, удирдагч багш, дадлага удирдагч, комиссын цэс, хуудаснаас холбогдох хэсэг нуугдаж, API 409 өгнө. Хэрэгжилт: `semesters.plan_enabled`, `logbook_enabled` (`migrations/0003_semester_features.sql`), `GET /api/me`-ийн `features`, `internship.features`.
- **Hash router** (`#/student/home`): ямар ч static hosting дээр (Cloudflare Pages, GitHub Pages, `python -m http.server`) refresh хийхэд 404 өгөхгүй. Хуудас бүр `import()`-оор шаардлагатай үедээ ачаалагдана. Хурдан шилжихэд хуучин хүсэлтийн хариу шинэ хуудсыг дардаггүй (token-оор хамгаалсан), хуудас солигдох үед 140 мс-ээс удвал skeleton (ижил хуудсыг дахин зурахад skeleton гаргахгүй), алдаа гарвал алдааны хуудас, шилжсэний дараа `h1` дээр фокус очно.
- **Төлөвүүд**: ачаалж байна (skeleton) / хоосон (`<empty-state>`) / алдаа / амжилт (toast) / маягтын талбарын алдаа бүгд хэрэгжсэн.
- **Хүртээмж**: semantic HTML (`button`, `label`, `dialog`, `details`, `table` + `caption`), keyboard-ээр бүгд ажиллана, `aria-live`/`role=status`, skip-link, `prefers-reduced-motion` хүндэтгэнэ. Өнгөний contrast-ыг хэмжиж шалгаагүй (хязгаарлалтыг 8-р хэсгээс үз).
- **Responsive**: `rem`, `clamp()`, grid/flex; 64em-ээс нарийн бол зүүн цэс нь доод хөвөгч цэс болно (4 цэс + «Цэс»).

## 7. Cloudflare дээр байршуулах (Workers + D1 + R2)

Нэг Worker нь UI-г (статик файл) болон `/api`-г хоёуланг нь үйлчилнэ. Build алхам **хэрэггүй**.

**А. Таны хийх зүйл (нэг удаа)**
1. Cloudflare бүртгэл (dash.cloudflare.com, үнэгүй).
2. **R2 (заавал)**: Dashboard → R2 Object Storage → «Enable / Purchase R2». Үнэгүй хэмжээ (10 GB), гэхдээ Cloudflare карт бүртгэхийг шаарддаг. Бүх файл (гэрээ, тайлан, дэвтрийн хавсралт, лого, загвар) R2-д хадгалагдана; `pm2-files` bucket-ийг `npm run cf:setup` үүсгэнэ (гараар: `npx wrangler r2 bucket create pm2-files`). Bucket байхгүй бол deploy амжихгүй.
3. **workers.dev дэд домэйн**: Dashboard → Workers & Pages-ийг нэг удаа нээж дэд домэйн сонгоно (шинэ бүртгэлд).
4. Компьютерт Node.js 22.13+ (`node -v`).

**Б. Байршуулах — нэг команд** (PowerShell, төслийн хавтсанд)
```powershell
npm run cf:setup
```
Скрипт дараахыг өөрөө хийнэ (дахин ажиллуулахад аюулгүй — хийгдсэн алхмыг алгасна):
`npm install` (wrangler) → Cloudflare-д нэвтрэх (хөтөч нээгдэнэ) → D1 `pm2-db` үүсгэж `database_id`-г `wrangler.toml`-д бичих → R2 `pm2-files` → 2 асуулт (Workers Paid эсэх, имэйл илгээгчийн хаяг — Enter дарж алгасаж болно) → migration → өгөгдөл (**демо** — туршилтад, эсвэл зөвхөн **админ** — жинхэнэ ашиглалтад) → deploy → `SIGNING_SECRET`-ийг санамсаргүйгээр үүсгэж тавих → хаягийг хэвлэнэ (`https://pm2.<таны-нэр>.workers.dev`).

Дараа нь:
```powershell
npm run cf:smoke -- https://pm2.<таны-нэр>.workers.dev   # 19 шалгалт: нэвтрэлт, D1, R2, гэрээ, тохиргоо (демо өгөгдөлтэй үед)
npm run cf:logs                                            # Worker-ийн log (имэйлийн түлхүүргүй үед урилга, нууц үг сэргээх холбоос, гарын үсгийн код энд)
npm run cf:deploy                                          # код өөрчилсний дараа: шалгалт → шинэ migration → deploy
```

**В. Заавал биш тохиргоо**
- **Имэйл (Resend)**: resend.com → өөрийн домэйн нэмж DNS-д SPF/DKIM бичлэг хийж баталгаажуулна → API key → `npx wrangler secret put MAIL_API_KEY`; `wrangler.toml`-ийн `MAIL_FROM`-г тэр домэйны хаягаар (жишээ нь `Дадлагын систем <no-reply@domain.mn>`) → `npm run cf:deploy`. Домэйнгүй бол Resend зөвхөн өөрийн бүртгэлийн и-мэйл рүү `onboarding@resend.dev`-ээс явуулна. Түлхүүргүй үед имэйл явахгүй, зөвхөн log-д бичигдэнэ (туршилтад хангалттай). Түр алдаа гарвал нэг удаа дахин оролдоно; олон урилгыг Resend batch API-аар 100-гаар илгээнэ.
- **CAPTCHA (Cloudflare Turnstile)**: Dashboard → Turnstile дээр widget үүсгэж site key-г `wrangler.toml`-ийн `[vars]`-д `TURNSTILE_SITE_KEY`, secret-ийг `npx wrangler secret put TURNSTILE_SECRET`. Тохируулсан үед байгууллага бүртгүүлэх маягтад widget гарна.
- **Өөрийн домэйн**: домэйн Cloudflare дээр байвал `wrangler.toml`-ийн `[[routes]]` хэсгийг идэвхжүүлнэ (эсвэл Dashboard → Workers → pm2 → Settings → Domains).

**Г. Тохиргооны тайлбар**
- **Нууц утга** (`wrangler secret`, `wrangler.toml`-д бичихгүй): `SIGNING_SECRET` (заавал — гэрээний гарын үсгийн нотолгоо; тохируулаагүй бол гарын үсэг зурахад 503; нэг удаа өгөөд **бүү соль**), `MAIL_API_KEY`, `TURNSTILE_SECRET`. Шалгах: `npx wrangler secret list`.
- **`PASSWORD_ITERATIONS`** (`[vars]`): нууц үгийн PBKDF2 давталт. 100000 давталт ~16 мс CPU — Workers **Free**-ийн 10 мс хязгаараас хэтэрч нэвтрэхэд 1102 алдаа гарах эрсдэлтэй тул Free-д 50000 (~7 мс), Paid-д 100000. Хэш бүр өөрийн давталтын тоог хадгалдаг тул солиход хуучин нууц үг ажилласаар; тоог нэмбэл хэрэглэгч нэвтрэх үед шинэ хэш болно.
- **Хязгаар**: D1-ийн нэг query-д 100-аас ихгүй параметр — олон id-тай шүүлтүүрийг `json_each(?)`-ээр нэг параметрээр дамжуулна. Workers Free-д нэг хүсэлтэд гадаад `fetch` 50 хүртэл (имэйлийг batch-аар).
- **Log**: `[observability]` идэвхтэй — Dashboard → Workers → pm2 → Logs.
- **Демо файлууд**: демо өгөгдлийн файлууд (`seed/...`) R2-д байхгүй тул татахад нэг хуудас «Demo file» PDF буцаана (`server/lib/files.js`). Шинээр байршуулсан файл R2-д хадгалагдана.
- Статик файлаас `.assetsignore`-д заасан backend файлууд (server/, migrations/, scripts/…) нийтлэгдэхгүй.
- Гараар (скриптгүй) хийх бол: `npx wrangler d1 create pm2-db` → id-г `wrangler.toml`-д → `npx wrangler r2 bucket create pm2-files` → `npm run cf:migrate` → `node scripts/seed.mjs --admin you@school.edu "НууцҮг123" > admin.sql` → `npx wrangler d1 execute pm2-db --remote --file admin.sql` → `npm run cf:deploy` → `npx wrangler secret put SIGNING_SECRET`.

**Д. Cloudflare-ийн runtime-ийг өөрийн компьютер дээр шалгах** (заавал биш)

`npm run dev` нь Node-ийн SQLite/файлын систем ашигладаг. Cloudflare-ийн жинхэнэ runtime (workerd)-ээр:
```powershell
copy .dev.vars.example .dev.vars              # SIGNING_SECRET-тэй (MAIL_* мөрүүдийг устгавал имэйл log-д)
npx wrangler d1 migrations apply pm2-db --local --persist-to .wrangler/state
node scripts/seed.mjs --file .data/seed.sql
npx wrangler d1 execute pm2-db --local --persist-to .wrangler/state --file .data/seed.sql
npm run cf:local                              # http://localhost:8787
node scripts/smoke.mjs http://localhost:8787  # өөр цонхонд
```

## 8. Одоогийн хязгаарлалт (шударгаар)

- **Хэл**: интерфэйсийн бичиг Монгол; PDF, CV, UI/UX, API зэрэг энгийн ойлгогддог техникийн нэр томьёо, и-мэйл, файлын нэр англиар үлдсэн. Файл сонгогч Монголоор (`core/file-picker.js`). Огнооны талбар нь браузерийн өөрийн `<input type="date">` тул календарь нь хэрэглэгчийн браузерийн хэлээр харагдана.
- **Демо файлууд**: демо өгөгдлийн загвар, тайлан, скан зэрэг нь (локал болон Cloudflare-д) «Demo file» гэсэн нэг хуудас PDF-ээр орлуулагдана; шинээр байршуулсан файл хэвийн.
- **Цагийн ажил** (Cron Trigger) хийгдээгүй: огнооноос хамаарах шилжилт (дадлагын хугацаа дуусахад тайлан нээгдэх) оюутан системд хандах үед хийгдэнэ; өдөр бүрийн сануулга байхгүй.
- **И-мэйл**: `server/lib/mail.js` нь Resend-ээр илгээнэ (`MAIL_API_KEY`, `MAIL_FROM`; §7). Түлхүүр тохируулаагүй үед зөвхөн log-д бичигдэнэ. Түр алдаанд нэг удаа дахин оролддог, түүнээс хойш дараалал (queue) байхгүй — хэрэглэгч дахин хүснэ.
- **Спамаас хамгаалалт**: давтамжийн хязгаар нь IP-ээр (нэг IP-ийн ард олон хэрэглэгч — сургуулийн сүлжээ — нэг хязгаарыг хуваалцана); нууц үг сэргээх, нэвтрэхэд CAPTCHA байхгүй (зөвхөн байгууллага бүртгүүлэх маягтад, Turnstile тохируулсан үед).
- **Гуравласан гэрээ**: тоон гарын үсэг нь дотоод энгийн цахим гарын үсэг (хуулийн «тоон гарын үсэг» биш; e-ID Mongolia зэрэгтэй холбоогүй). Бодит цагийн шинэчлэл нь 4 секундийн polling (WebSocket биш). Дадлага удирдагч байгууллагын тамгыг өөрөө зураг болгон оруулна. SIGNING_SECRET-ийг сольвол өмнөх гарын үсгүүдийн `proof` шалгалт буруу гарна.
- Оюутанд нэг л идэвхтэй дадлага харагдана (өмнөх улирлын дадлага сонгогч байхгүй).
- Rubik фонт Google Fonts CDN-ээс ачаалагдана. Production дээр фонтын файлыг төсөлд хадгалж (`@font-face`) өөрийн домэйнээс өгөх нь дээр.
